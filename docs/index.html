COMPLETE GUIDE

第一次安裝完整教學

以下順序是依照目前程式實際執行內容整理。每個步驟完成並看到綠色 [OK] 後，再進行下一步。

系統Windows 10／11 x64

必須使用系統管理員權限，才能安裝工具、建立 MariaDB 服務並寫入 C:\Server。

網路保持穩定連線

安裝程式會從 GitHub、Visual Studio 與套件來源下載內容。中途不要關閉管理中心。

空間預留足夠磁碟空間

核心、客戶端資源、翻譯、Visual Studio Build Tools 與編譯結果都會占用空間。

資料先確認 C:\Server

更新會覆蓋 Git 已追蹤的本機修改；全部移除也會刪除伺服器相關目錄。

  1. 1

    下載與啟動

    開啟 RagnarokInstaller.exe

    EXE 會從 GitHub 下載最新版至桌面的 RagnarokInstaller-main，解壓縮後自動開啟完整專案的 Start.cmd。看到 Windows 權限提示時選擇「是」。

    完成時會看到Ragnarok Installer Manager v6.0 主選單與目前狀態。
  2. 2

    選項 1

    安裝／更新開發環境

    安裝或檢查 Git、7-Zip、Python、Visual C++ Runtime，以及 Visual Studio 2022 Build Tools。Visual Studio 安裝可能會在另一個視窗繼續執行，請等它真正完成。

    完成時會看到主選單上 Git、Python、Visual Studio Build Tools 顯示 [OK]。
  3. 3

    選項 2

    安裝／更新 MariaDB

    程式會檢查 MariaDB 用戶端、版本與 Windows 服務；未安裝時自動安裝，損壞時嘗試修復。舊的損壞資料會移至 C:\Server\Backups。

    完成時會看到MariaDB 顯示執行中；若提示重新啟動 Windows，請重開機後再繼續。
  4. 4

    選項 G

    執行一鍵初始化

    依序更新伺服器核心、WARP、ROenglishRE、NPC 中文化，接著建立資料庫、寫入設定、Clean + Build 並套用中文化。第一次建立資料庫可使用預設選擇；若偵測到既有資料，直接按 Enter 會保留資料。

    請不要關閉視窗編譯期間會顯示目前階段、耗時及正在處理的英文檔名；全部完成後不會自動啟動伺服器。
  5. 5

    選項 C

    啟動伺服器

    程式先確認四個 EXE 是否存在，再開啟 C:\Server\rAthena\runserver.bat，由官方腳本啟動並監看 login、char、map 與 web server。

    如果提示缺少 EXE先執行 4 編譯；若編譯失敗，按 A 查看 Compile.log。
  6. 6

    選項 9

    最後檢查安裝狀態

    確認目前核心、安裝路徑、MariaDB 服務、Python、PACKETVER，以及四個伺服器執行檔。正式對外開放前，務必修改預設帳密並設定防火牆。

    成功判斷四個伺服器 EXE 存在、MariaDB 正常執行，runserver 視窗沒有持續出現紅色錯誤。

COMMON SCENARIOS

之後要更新時怎麼選？

先依照你改動的內容選擇流程。伺服器執行中不要覆蓋設定或重新編譯。

更新伺服器核心

H→3→5→4→F→C

停止服務、同步最新版、清除舊結果、重新編譯、重套中文化後啟動。

只更新中文化資源

H→D→E→F→C

更新英文化與 NPC 中文化來源，再套用到目前核心並重新啟動。

修改 PACKETVER／核心設定

H→8→5→4→C

PACKETVER 屬於編譯設定，修改後必須 Clean、Build 才會生效。

只更新資料庫

H→7→C

偵測到既有資料時，直接 Enter 會保留資料；選擇全新建立會要求再次輸入確認文字。

BUILD & RUN

編譯與啟動怎麼分？

選項 5 · CLEAN

先清除舊結果

移除上次編譯留下的 EXE、程式庫與中間檔，讓下一次建置從乾淨狀態開始。

不會產生新的伺服器 EXE。

選項 4 · BUILD

再編譯新版本

使用 Visual Studio 2022 MSBuild，以 Release | x64 編譯官方 rAthena.sln。

畫面會顯示階段、耗時與正在處理的英文檔名。

選項 C · RUN

最後啟動服務

開啟 C:\Server\rAthena\runserver.bat，由官方腳本啟動並監看四個服務。

更新或重新編譯前，請先按 H 停止。

TROUBLESHOOTING

常見問題

選項 1 完成了，為什麼 Visual Studio 還在安裝？

Visual Studio Build Tools 會在獨立視窗執行。請等該視窗完成，再回主選單確認 Visual Studio 顯示 [OK]，否則選項 4 會找不到 MSBuild。

G 一鍵初始化是否包含所有環境安裝？

不包含。第一次使用必須先執行選項 1 安裝開發環境，再執行選項 2 安裝 MariaDB，兩者完成後才執行 G。

更新時出現 index.lock 錯誤怎麼辦？

先確認沒有其他 Git 程序執行。新版管理中心會偵測殘留鎖定檔，確認安全後自動清除並繼續更新。

更新時顯示本機修改會被覆蓋，資料會不見嗎？

選項 3、6、D、E 會以 GitHub 最新內容同步其儲存庫，Git 已追蹤檔案的本機修改可能被覆蓋。資料庫不在這些 Git 儲存庫內，但重要自訂腳本與設定仍應另行保存。

選項 4 和選項 5 有什麼不同？

選項 5 只執行 Clean；選項 4 才會 Build。需要完整乾淨編譯時，依序執行 5、4。

編譯畫面沒有動，是不是當機？

藍色面板的 Elapsed 時間會持續增加，下方也會顯示新出現的英文檔名。詳細錯誤則保存在 Logs\Compile.log。

修改 PACKETVER 後要做什麼？

先按 5 清除舊編譯結果，再按 4 編譯，最後按 C 重新啟動伺服器。

需要安裝 CMake 嗎？

不需要。本工具直接使用 rAthena 官方 rAthena.sln，透過 Visual Studio 2022 MSBuild 以 Release | x64 建置。

可以直接下載缺少的 DLL 嗎？

不要從不明網站單獨下載 DLL。請執行選項 1，讓管理中心安裝正確的 Visual C++ Runtime 與建置工具。
